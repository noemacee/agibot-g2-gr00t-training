# G2 training: current status and remaining work

The PR contains the dataset adapter, both modality configurations, and a
[training entry point](../../scripts/agibot_g2/run_training.py) for statistics,
GPU smoke runs, fine-tuning, and held-out open-loop evaluation. It does not yet
contain a trained G2 checkpoint or verified G2 forward kinematics.

The two policies remain:

- **Joints:** 42 body/head/arm/hand joint targets per timestep.
- **EEF + joints:** both arm poses plus 28 body/head/hand joint targets, totaling
  40 action values in the chosen XYZ + rotation-vector representation.

The joint route can start once its dataset, calibration, splits, statistics,
and GPU environment are ready. It does not need FK or IK. The EEF route also
needs the calibrated FK provider to create its labels. **IK is needed for robot
execution, not for offline EEF training.** Existing GR00T model/trainer code is
used by both routes; there is no new model architecture in this PR.

## Review checklist: inputs and dataset quality

- [ ] Finish the cleaned upload and record an immutable dataset revision. The
  earlier audit used an intermediate 45-episode snapshot and must be repeated
  on the final data.
- [ ] Download the complete snapshot to an unchanged local directory, including
  all three camera streams.
- [ ] Run the [adapter inspection](ADAPTER.md#1-inspect-the-completed-snapshot).
  Inspect counts per episode and retained task phases, not only total rows.
- [ ] Complete all 42 joint calibration entries. Confirm hand command encoding
  separately from hand feedback encoding. Affine mappings are supported; a
  nonlinear mapping requires additional conversion code if the hardware uses one.
- [ ] Review task success/failure and select train/validation/test/excluded
  episodes. Fill `recording_groups` where several episodes share a source take.
- [ ] Review the manifest's invalid-hand counts and hold-position imputations.
  The default preserves every selected frame; imputation is a practical fallback,
  not a recovery of the missing demonstrator command. If that assumption is
  unsuitable, repair labels or implement validity-masked losses and statistics;
  masking is not in this PR.
- [ ] For EEF: obtain the calibrated URDF/robot description and implement
  `compute_poses` using the [FK-provider contract](ADAPTER.md#4-prepare-eef--joint-prediction).
  Confirm the robot root frame, both TCP definitions, units, joint mapping, and
  body-joint contribution. Validate measured-joint FK against an independently
  understood pose reference before generating command-pose labels.
- [ ] Run the adapter and review `preparation_manifest.json`, retained video
  segments, timestamp alignment, target ranges, and output modality mappings.
  Prepare both variants together when FK is ready to obtain identical splits
  and retained frames for the comparison.

The current snapshot has 102,807 frames in the selected 44 episodes before
hand-target imputation. The default adapter keeps all 102,807 frames, while
recording 30,514 rows that contain at least one invalid hand dimension. The
strict optional filtering mode would retain 72,167 frames after its 16-frame
segment rule. These are diagnostics for this snapshot, not results for the
final cleaned dataset. Real dataset videos and physical calibration have not
been validated by the synthetic tests.

## Run the training stages

Activate the main GR00T Python environment installed for the training GPU
platform using the [upstream installation instructions](../../README.md#installation).
The adapter's small CPU script environment is not the training environment.
Confirm model access and use a downloaded, pinned base checkpoint via
`--base-model /data/models/gr00t-n1.7-pinned` if reproducible model revisions are
required. The default model identifier is `nvidia/GR00T-N1.7-3B`.

Run from the repository root. Each stage needs a new run directory, outside the
prepared dataset. Commands below use the joint variant; substitute `eef` and
its prepared root/run directories to run the second policy.

### Statistics

```bash
python scripts/agibot_g2/run_training.py stats \
  --prepared-root /data/g2-prepared-both --variant joints \
  --run-dir /data/g2-runs/joints-stats
```

This invokes upstream GR00T statistics on training data only, then copies those
statistics into any prepared validation/test roots. It does not fit separate
normalization to held-out episodes. Repeat per variant. The wrapper checks that
held-out statistics match training before evaluation. Regenerate statistics
when changing the modality configuration, action horizon, or prepared data.
The provided wrapper/configurations use a sixteen-step horizon.

### GPU smoke run

```bash
python scripts/agibot_g2/run_training.py smoke \
  --prepared-root /data/g2-prepared-both --variant joints \
  --run-dir /data/g2-runs/joints-smoke \
  --base-model /data/models/gr00t-n1.7-pinned \
  --batch-size 8 --num-gpus 1
```

The default smoke run performs 20 training updates and saves a checkpoint. It
loads pretrained weights and runs the actual trainer; it is not a fake or
weights-skipping test. It uses the supplied training split, so it is **not**
a one-episode overfit experiment. To test memorization, first prepare a separate
small dataset root containing one or two training demonstrations and run a
longer experiment on that root.

- [ ] Verify decoding, finite loss/gradients, memory use, throughput, and all
  expected output groups on the actual GPU.
- [ ] Verify that the smoke checkpoint can be loaded for inference.
- [ ] Run a small overfit experiment and confirm that predictions improve beyond
  a constant/hold-current-state baseline before spending a full training budget.

### Full fine-tuning

```bash
python scripts/agibot_g2/run_training.py train \
  --prepared-root /data/g2-prepared-both --variant joints \
  --run-dir /data/g2-runs/joints-train \
  --base-model /data/models/gr00t-n1.7-pinned \
  --batch-size 8 --num-gpus 1 --max-steps 2000
```

The wrapper uses all prepared episodes (`episode_sampling_rate=1.0`), the
selected modality configuration, and the upstream defaults that freeze the
vision/language backbones and tune the projector/action model. Defaults are
starting settings, not performance claims. `--learning-rate` and `--workers`
can be adjusted. The batch size must divide evenly across the selected GPUs.
The wrapper uses fresh runs; checkpoint resumption remains available through
upstream `launch_finetune.py` directly.

Each stage prints its command, writes subprocess output to `command_*.log`,
and records a `run.json` containing commands, input metadata/config/statistics
hashes, and success/failure status. Training checkpoints are written under
`RUN_DIR/checkpoints/checkpoint-STEP`. A failed subprocess keeps its log and
marks the run failed. No completed run is silently overwritten.

Add `--dry-run` to any stage to validate its local prerequisites and print its
commands without launching jobs or writing files. Training dry runs still need
prepared data and statistics; evaluation dry runs also need a checkpoint path.
A dry run does not verify CUDA, model downloads, or forward/backward execution.

### Held-out evaluation

```bash
python scripts/agibot_g2/run_training.py eval \
  --prepared-root /data/g2-prepared-both --variant joints \
  --run-dir /data/g2-runs/joints-validation-2000 \
  --checkpoint /data/g2-runs/joints-train/checkpoints/checkpoint-2000 \
  --split validation
```

This evaluates every prepared episode in the requested split over its full
length, producing one plot and one subprocess log per episode. It uses separate
upstream evaluation processes so plot paths cannot overwrite one another; the
checkpoint is reloaded for each episode, which adds startup overhead. Use a
checkpoint trained with the matching variant and prepared dataset. Select
checkpoints using validation, then run `--split test` on the selected model.

- [ ] Compare checkpoints on validation; record the exact selected checkpoint.
- [ ] Report the untouched test split for both variants under matched data,
  horizon, base model, and training budget.
- [ ] Interpret joint errors by joint and unit, and EEF errors as position and
  orientation errors. Upstream aggregate MSE/MAE and plots are available through
  the wrapper. A separate report computing FK-based cross-model TCP errors and
  rotation-geodesic metrics still needs to be implemented for a rigorous
  joint-vs-EEF comparison; mixed-unit aggregate MSE is not that comparison.

## After training: robot execution

These items are required to deploy and compare task performance, but do not
block offline fine-tuning:

- [ ] Joint controller: map named model outputs to robot commands with the
  verified units, limits, and command timing.
- [ ] EEF controller: implement/validate IK or Cartesian control, TCP transforms,
  reachability checks, and coordination with body/head/hand targets. Use measured
  arm joints to seed redundant-arm IK.
- [ ] Measure inference/transport latency, choose how much of each sixteen-step
  chunk to execute before replanning, and test synchronized three-camera inputs.
- [ ] Validate in replay/simulation, then supervised robot trials. Compare task
  success, drops, interventions, collisions, and execution time under matched
  initial conditions.

## What review of this PR establishes

The code and tests are reviewable now. Merge approval would accept the adapter,
training orchestration, and documented contracts. It would not establish that
the final dataset, calibration, physical FK, GPU training, or robot policy have
already been validated. Each unchecked item above needs its own evidence as
we execute the training workflow.
